# 架构决策 001：受治理工作图继续使用事务数据库

| 项目 | 结论 |
|---|---|
| 状态 | 已接受并随生产提交 `34d04326d1d16ba92994107eb2f44bf89d74c759` 部署；业务能力仍未放量 |
| 日期 | 2026-08-12 |
| 决策范围 | Graph Contract v1 的追加式投影、四类有界解释查询与项目驾驶舱 |

## 背景

Foursday 的领域事实已经分布在项目清单、配方、任务、计划、步骤、审批、能力预算、证据、记忆、触发器和时间返还账本中。受治理工作图的职责是把这些关系投影为可解释记录，而不是成为新的授权来源或替换领域状态机。

本决策必须同时满足：

- 图上可达不能产生授权，预算仍由领域账本原子扣减；
- 每次查询只允许一个租户和一个项目，并限制深度与结果数；
- 运行观察只追加，重放幂等，隐私擦除与领域数据在同一事务内覆盖图记录；
- SQLite 与 PostgreSQL 具有相同契约；
- 投影失败时，执行前失败关闭，终态结果可从领域事实确定性重放。

## 备选方案

| 方案 | 优点 | 代价与风险 |
|---|---|---|
| 继续使用 SQLite/PostgreSQL | 复用现有事务、加密、租户隔离、备份、迁移和擦除链路 | 只适合有界遍历；复杂开放式图分析会增加 SQL/内存查询成本 |
| 直接引入专用图数据库 | 原生多跳遍历和图分析能力强 | 新增双写、权限、备份、密钥、擦除、迁移和运维边界，容易让图事实漂移 |
| 事务库加异步图副本 | 可兼顾事务事实与图查询 | 必须新增可靠发件箱、重放、对账和删除传播；当前需求没有证明复杂度值得 |

## 决策

Graph Contract v1 继续使用 SQLite（本地）和 PostgreSQL（生产形态）保存加密的节点与关系观察，不引入专用图数据库，也不建立第二套授权或记忆事实来源。

领域记录先提交，图投影随后按稳定领域版本确定性生成。计划执行前必须成功持久化设计图，否则不得开始副作用；终态图采集失败由执行器按领域更新时间自动重放。相同领域版本生成相同节点与边编号，因此重试不会重复。这个“领域事实可重放 + 执行前失败关闭”边界取代双写事务，并避免图故障回滚已经完成的外部动作。

四类解释查询继续在应用层执行，固定限制为单租户、单项目、最大深度 8、最多 500 个节点或关系；所有回答都标记为非权威解释，授权、预算、审批和执行仍回到领域服务判断。

## 证据

2026-08-12 的发布验证包括：

- `npm run check:full`：665 项通过，覆盖 SQLite 与一次性隔离 PostgreSQL，0 失败、0 跳过。
- `npm run graph:benchmark`：30 个计划、242 个节点、331 条关系、100 次迭代；本机 SQLite 的四类查询加存储读取 P50 为 19.015 ms，P95 为 22.114 ms，最大 26.918 ms。
- 反向测试覆盖过期授权、配方漂移、跨项目记忆、缺审批、缺来源、缺证据、并发追加、投影重试和隐私删除。

该基准只是本机候选数据，不是生产 SLO，也不能证明任意规模的开放式图遍历。

## 何时重新评估

满足任一条件时重新比较专用图数据库或异步图副本：

1. 使用真实脱敏生产形态数据，在同等加密和项目隔离下，四类查询 P95 连续超过 100 ms；
2. 产品必须支持超过 500 条结果或深度 8 的在线遍历，且无法通过预计算投影解决；
3. 出现当前事务模型难以维护的图分析需求，而不是只为了展示关系；
4. 已经具备双写对账、删除传播、备份恢复、租户隔离和故障演练的明确运维预算。

在这些条件出现前，专用图数据库会增加风险而不会提高个人 AI 工作系统的核心价值。
