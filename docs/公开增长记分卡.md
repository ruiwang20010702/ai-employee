## 计数契约

### 成功安装

只有体验者自愿报告固定 SHA 的一条命令成功启动，或者维护者在全新工作区直接复现并
留下有界证据时，才计为一次成功安装。包下载量、CI 任务、重复重试和 `reuse:verify`
创建的两个测试工作区都不计数。

外部用户可以使用 Issue #50 中的有界模板；安装签到不会升级成验证闭环用户，也不会产生
仓库或生产权限。

固定提交的 Web 接入页只在只读 readiness 返回 `externalSystemsModified: false` 后生成同一份有界模板。复制发生在本机，打开 Issue #50 和发布评论仍是两次独立的自愿操作；一旦开始准备 fork，“尚未创建 fork”的安装签到复制入口会被禁用。

公开证明不得包含用户名、邮箱、本机路径、令牌、模型输出、私有仓库身份或公司资料。
预览成功不代表已经创建 fork、分支或 PR，更不代表已经合并、部署、发送或执行计划。

### 完成验证闭环的用户

每个明确同意参与的独立用户最多计一次，不按闭环次数重复累计。至少要有一份绑定唯一
Issue 与 Draft PR 的有效证据：完整计划精确审批、目标回读、项目记忆单独确认、时间返还
单独确认均成立。维护者仍需独立回读公开 Issue 和 Draft PR；完整本地证据包不公开上传。

10 分钟接入漏斗使用两段诚实证据：体验者填写的“安装→预览”观察值，以及纳入证据完整性摘要的“本地服务启动→结果确认”单调时钟自动耗时。后者会细分计划生成、人工审查、审批后执行和结果确认，但明确不包含首次包下载；任何一段都不能单独证明完整 10 分钟承诺。

### 外部贡献者

非维护者贡献合入默认分支后才计为已完成外部贡献者。认领留言、Draft PR、Review 和
未完成尝试都是有价值的漏斗信号，但不能提前记为完成。

### 社区配方或适配器

非维护者贡献的无凭据、可版本化配方或适配器，通过契约测试、安全审查并合入后才计数。
改名、重复内容、维护者测试夹具和依赖隐藏生产权限的连接器不计数。

### GitHub Star

只使用 GitHub 仓库公开计数；不购买、不交换、不自动化刷 Star。

## 证据与隐私边界

- 可以公开：Issue/PR 链接、固定提交、受限的计划与证据哈希、Draft/打开状态、自愿反馈和汇总数量。
- 只留本地：完整验证证据包、本机路径、运行日志、项目记忆正文、模型输出和私有仓库信息。
- 禁止公开：凭据、令牌、真实工作消息、员工标识、内部源码或生产数据。
- 增长和产品权限相互独立：任何目标都不能开启生产发送、自动执行、主动工作、合并或部署。

这份记分卡按保守口径计算：缺少证据就是“不计数”，不是“应该已经完成”。
