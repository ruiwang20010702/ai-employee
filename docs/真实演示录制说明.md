# 75 秒真实演示录制说明

[观看 v0.5 候选版真实演示](../assets/foursday-v0.5-demo.mp4)。演示使用合成
[Issue #29](https://github.com/ruiwang20010702/foursday/issues/29)，并回读核对生成的
[Draft PR #39](https://github.com/ruiwang20010702/foursday/pull/39)。全程未合并、未部署，
生产自动发送、计划执行和主动工作均保持关闭。

公开文件为 75 秒、1280×720、H.264、无音轨并带画面字幕。维护者已经对当前媒体摘要对应的
完整画面做过人工隐私复核，确认未展示凭据、私有仓库或用户专属本机路径；画面中的仓库目录统一为
合成路径 `/workspace/foursday`。运行 `npm run demo:verify` 可核对媒体结构、视频与海报摘要、
公开 Issue/PR 以及“未合并、未部署”边界。该命令的作用是把人工画面复核绑定到发布字节，
不声称能够自动 OCR 或逐像素识别隐私。

v0.5 的公开演示必须来自同一次真实闭环，不能把本地预览、无关 PR 和模拟结果剪接成“已完成”。英文[录制契约与分镜](./en/demo.md)是默认公开版本，中文统一口径如下：

1. 使用公开、合成内容的 GitHub Issue 和干净候选提交。
2. 先展示五步预览与 `0 external systems touched`，再创建本地加密会话。
3. 清楚展示完整计划哈希、一次性审批及“不能合并、不能部署”。
4. 连续展示补丁、隔离分支、登记测试、受限推送、Draft PR 逐字段回读。
5. 打开同一个 Draft PR，核对草稿状态、分支、提交、标题、基础分支与测试。
6. 最后分别确认项目记忆候选和时间返还，不把模型估算自动计入结果。
7. 确认后下载证据包，展示 `verified_closed_loop` 和完整性摘要。
8. 结尾保留候选 SHA、公开 Issue/PR、运行时、测试结果和“未合并、未部署、生产发送仍关闭”。
9. 将人工隐私复核写入 `assets/foursday-v0.5-demo.manifest.json`，并绑定视频与海报的 SHA-256 摘要。

当前视频证明维护者路径和公开 Issue 到 Draft PR 的回读闭环，但不代表外部可复现性已经验收。
v0.5 的公开验收仍要求 10 位独立测试者依据 Quick Start 复现，并提交不含隐私的反馈。
