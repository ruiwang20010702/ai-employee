# 首次贡献任务

> 文档角色：社区首次贡献指南；任务可用性以 GitHub Issue 为准。

Foursday 的首批 `good first issue` 聚焦“让陌生用户更容易完成前十分钟”，同时避开生产发送、计划放量、凭据、部署和新增外部写入。英文[首次贡献入口](../en/first-contributions.md)是对外默认清单，下面是中文口径：

| 编号 | 用户结果 | 主要范围 | 领取入口 |
|---|---|---|---|
| GFI-001 | 可复制完整计划哈希，并向键盘与读屏用户反馈成功 | Web 接入页 | [Issue #3](https://github.com/ruiwang20010702/foursday/issues/3) |
| GFI-002 | 对常见接入失败提供不泄露本机信息的修复指引 | Web 接入页与文档 | [Issue #4](https://github.com/ruiwang20010702/foursday/issues/4) |
| GFI-003 | 增加一个无凭据、无外部副作用的社区配方示例 | 配方示例 | [Issue #5](https://github.com/ruiwang20010702/foursday/issues/5) |
| GFI-004 | 覆盖一个 OpenAI-compatible 提供方边界用例 | 提供方契约测试 | [Issue #6](https://github.com/ruiwang20010702/foursday/issues/6) |
| GFI-005 | 增加可重复的手机端接入页视觉检查 | 贡献者工具 | [Issue #7](https://github.com/ruiwang20010702/foursday/issues/7) |

5 个任务都已经开放。开工前先在对应 Issue 留言；GitHub Issue 的打开状态、认领和讨论是当前事实来源，仓库内 `.github/ISSUE_DRAFTS/` 文件继续作为范围与验收条件的版本化契约。

GFI-003 可以先用独立的只读命令校验单个配方，再运行完整检查：

```bash
npm run extensions:validate -- --recipe examples/recipes/<file>.json
npm run check
```

第一条命令不读取凭据、不安装扩展、不联网，也不会执行配方。
