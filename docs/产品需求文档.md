# Foursday 产品需求文档

## 1. 产品目标

Foursday 让个人拥有一个由自己记忆驱动、能在真实项目中自主工作的 AI 工作分身，从而减少本人必须亲自处理的重复工作时间。

## 2. 目标用户

需要同时处理多个项目、已经使用 Git/Markdown/知识库，并愿意让 AI 在受隔离工作环境中完成可恢复工作的个人专业用户。

## 3. 核心体验

1. 用户安装 Foursday Profile，并配置可信联系人、项目注册表和个人 gbrain 只读凭据。
2. 可信联系人从钉钉或 Foursday 支持的消息平台提出问题或工作请求。
3. Foursday 自动识别项目；不确定时只问一个最小澄清问题。
4. Codex 在同一 Foursday Session 中持续调用工具，直到工作完成或得到明确阻塞。
5. 程序回读文件、命令、测试和发送结果，AI 根据证据自然回复。
6. 用户手工接管时，中断尚未完成的工作。

## 4. 默认权限

可信联系人默认可以请求普通可恢复工作：搜索、分析、计算、整理文档、修改项目文件和运行测试。

以下动作必须经过独立授权出口，不能由普通工具循环直接完成：

- Git push、PR merge、Release 和包发布；
- 生产部署、生产数据库写入和系统服务控制；
- 不可恢复删除；
- 付款、合同和人事决定；
- 秘密读取或外发；
- 代表负责人作不可撤销承诺。

陌生联系人和未 `@` 的群消息不能建立 Agent Session。

## 5. 项目路由

项目注册表只包含：项目 ID、名称、别名、绝对目录、Git remote、相关 gbrain slugs 和运行说明。工作区权限由Foursday统一策略强制，项目文件不能自行声明更高权限。

不得加入 requester、capability、业务指标、JSON Pointer、回复模板或秘密。

同一会话优先复用已有项目；新出现的明确项目别名可以切换；同强度多项目命中必须澄清。

## 6. 记忆

个人 PRIVATE gbrain Git 是唯一长期业务知识权威。Foursday 按项目精确读取，不复制正文。

稳定工作发现可以进入加密候选队列；只有通过证据、隐私、幂等、冲突和 Git 精确回读后，才写入个人 gbrain。临时消息、草稿、凭据、敏感人物信息和执行租约不得晋升。

## 7. P0 验收

### 事实与追问

可信联系人询问项目当前状态时，Foursday 自动进入真实项目，读取现有脚本、台账和输出，自主计算并自然回答。后续询问通过率、剩余量、异常批次、成本或原因时，复用同一 Agent Loop，不新增专用指标代码。

### 项目工作

可信联系人要求整理文档、运行分析或修改代码时，Foursday 完成修改、运行项目测试、回读结果并回复；推送和部署仍被阻断。

### 安全

陌生人、未 `@` 群消息、跨项目路径、秘密访问、网络外传和高风险命令全部失败关闭；人工接管能中断在途工作；发送结果未知时不自动重试。

## 8. 非目标

- 自研完整 Agent Runtime；
- Hermes Fork 或核心补丁；
- 第二套个人知识库；
- 为每个问题维护 capability 或固定模板；
- 在安装时自动启动、发送或继承机器上的既有权限。
