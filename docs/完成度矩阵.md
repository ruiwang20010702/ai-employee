## 删除区

以下概念已从个人默认架构撤销。没有新的架构决策和验收证据，不得重新引入：

| 已撤销概念 | 为什么撤销 | 替代方案 | 允许重新评估的条件 |
|---|---|---|---|
| `project_evidence_read` | 每个业务问题都需要专用代码 | Hermes/Codex 在真实项目自主检索和计算 | 只可作为可选企业确定性工具，不得成为个人默认入口 |
| `produced_questions` 等固定指标 | 把 Agent 退化成指标问答机器人 | 当前文件证据 + 通用 Agent Loop | 外部系统提供正式 typed API 且作为工具而非回答模板 |
| 固定 JSON Pointer 回复 | 与业务文件结构强耦合，扩展成本高 | Agent 读取脚本、台账和汇总并引用证据 | 企业审计场景单独启用 |
| 逐联系人项目 requester | 重复人工配置，阻止可信联系人工作 | 入口 allowlist + 项目自动路由 | 多租户企业组织隔离模式 |
| 固定业务回复模板 | 不能处理追问、解释和新问题 | 自然生成 + 数字/文件回读 | 法规要求固定披露文本 |
| 自研完整 Agent Loop | 重复 Hermes/Codex 成熟底座 | 固定上游 + 外部插件/Profile/Skills | Hermes 无法通过扩展或小补丁支持核心需求 |
| 独立 Foursday 长期知识库 | 与个人 gbrain 重复、冲突和删除漂移 | 个人 gbrain 唯一长期权威；Hermes DB 只存运行上下文 | 多用户产品需要真正租户隔离时重新设计 |
