# Foursday 完成度矩阵

这张表只回答三件事：已经具备什么、证据在哪里、还差什么。代码通过不等于生产放量，生产运行、人工质量和长期观察分别判断。`main` 的能力状态按本表更新；具体生产提交、迁移数量、服务健康和开关必须以管理台、`production:verify` 与不可变 `current` 回读为准，避免把一次历史快照长期写死在文档里。公开预览版 `v0.6.0-rc.1` 仍是最新带标签版本；`main` 与本机生产可以包含其后的候选改动。

统一口径：“已实现”表示代码和自动测试具备；“已部署”表示当前主机正在运行；“已授权”表示具体项目和请求人可以使用；“可放量”还必须同时通过健康、人工质量和长期指标门槛。四者不能互相替代。

## 统一上线顺序

```mermaid
flowchart LR
    A["填写独立生产配置"] --> B["只读迁移预检"]
    B --> C["加密备份"]
    C --> D["显式数据库迁移"]
    D --> E["严格只读诊断"]
    E --> F["合成 Codex 草稿探针"]
    F --> G["安装或更新服务"]
    G --> H["目标版本服务部署验证"]
    H --> I["严格业务就绪与影子验收"]
    I --> J["人工质量和长期 SLO 门槛"]
    J --> K["另行审批放量"]
```

任何一步失败都停止后续步骤。检查不能暗中迁移，迁移不能暗中部署，部署不能自动打开发送或计划执行。
