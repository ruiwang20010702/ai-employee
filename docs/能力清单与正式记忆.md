# Foursday 自主权限、企业治理与记忆边界

状态：V3 个人模式以 Hermes 通用 Agent Loop 为默认；本文件同时说明旧 Runtime / Enterprise Mode 的兼容治理。

## 1. 个人模式不以 capability 清单为入口

可信联系人提出普通可恢复工作后，Foursday 自动路由项目并完成工作，不要求负责人先添加 requester、能力、计划或审批。

| 默认允许 | 证明方式 |
|---|---|
| 读取项目文件和 Git 状态 | canonical workspace + 工具轨迹 |
| 搜索、计算和运行分析脚本 | 命令、cwd、退出码、输出摘要 |
| 创建/修改文档和代码 | 文件哈希与回读 |
| 建本地分支或隔离工作树 | Git 回读，不推送 |
| 构建、检查、测试和继续修复 | 测试命令与最终结果 |
| 制作可审查交付物 | 目标路径、格式和摘要 |
| 自然回复 | DWS 服务器消息 ID 与精确正文回读 |

程序负责身份、项目、隔离、证据和停止边界；模型负责理解、工具策略和自然表达。

## 2. 独立高风险边界

以下动作不能由普通 Agent 工具直接完成：

- Git push、PR merge、Release 和 package publish；
- 生产部署、集群变更和生产数据库写入；
- 不可恢复删除和系统服务控制；
- 付款、合同、人事录用/辞退/薪酬/绩效决定；
- 秘密、凭据或敏感材料外发；
- 代表负责人作不可撤销承诺。

边界由 `foursday-high-risk-boundary` Hook、逐工具沙箱、无网络终端和 DWS 最终出站检查共同执行。Hook 配置异常时必须失败关闭（fail closed），不能失败开放。

## 3. 可选 Enterprise / Governed Mode

旧 Node.js Runtime 的 project manifest、capability、budget、approval、recipe 和 step adapter 保留，用于：

- 多租户或组织级权限；
- 受监管的确定性流程；
- 生产系统逐字段授权和回读；
- 次数、费用或时间预算；
- 必须审批的办公与发布动作；
- 当前生产迁移和回退。

这些配置不再成为个人模式的前置条件，也不能把 Hermes 普通工作重新限制成“未登记能力就回复没有能力”。

### 3.1 旧能力等级

| 等级 | 旧 Runtime 示例 | V3 处理 |
|---|---|---|
| L0 | 观察、查询、草稿 | 普通工作默认允许 |
| L1 | 研究、分析、知识读取 | 普通工作默认允许，仍受项目沙箱 |
| L2 | 文档、代码、本地任务 | 可恢复范围默认允许，必须验证 |
| L3 | 外部写入、推送、办公创建 | 进入独立出口或企业审批 |
| L4 | 部署、线上改数、合同、人事、付款 | 强制负责人授权，普通 Agent 不持凭据 |

### 3.2 企业计划与审批

Governed Mode 可继续使用完整计划哈希、审批有效期、次数预算、执行租约、副作用账本和目标回读。相关实现属于当前生产兼容层，技术细节以代码和[生产运维手册](./生产运维手册.md)为准。

## 4. 记忆不是能力审批的副产品

```text
个人 PRIVATE gbrain Git → 长期业务知识唯一权威
个人 gbrain PostgreSQL  → 可重建索引
Hermes Session DB       → 会话、工具和短期执行
Foursday PostgreSQL     → 旧 Runtime 兼容状态与待迁移审计
```

### 4.1 读取

- 项目注册表只给出精确 gbrain slugs；
- 宿主桥接要求 `default + read-only OAuth`；
- OAuth secret 不进入 Agent 工具环境；
- 读取内容有大小、凭据、敏感人物和 confidential 过滤；
- 变化中的数量和状态仍须回到项目文件。

### 4.2 写入

V3 P0 不自动把 Hermes Session 内容写回个人 gbrain。稳定知识晋升仍应经过：来源 → 去重 → 隐私 → 冲突 → Markdown write-through → 精确回读。

消息原文、草稿、工具租约、审批和临时状态永不晋升为长期知识。

### 4.3 删除和撤销

个人 gbrain 的删除、权限回收和 Git 历史由个人库负责。Foursday 不缓存个人正文，因此下一次检索立即服从当前 gbrain 状态。

## 5. 已撤销方向

以下内容禁止作为个人默认能力重新出现：

- `project_evidence_read`；
- `produced_questions` 等业务专用指标；
- 固定 JSON Pointer 求和；
- 固定数量回复模板；
- 逐联系人项目 requester；
- 为每个新问题新增 capability 或 adapter。

完整删除区见[完成度矩阵](./完成度矩阵.md)。
