# Autonomy, Enterprise Governance, and Memory

Status: Hermes general Agent Loop is the V3 personal default. Capability manifests remain optional Enterprise / Governed Mode and the compatibility boundary for current production.

## Personal default

Allowlisted users can request reversible project work without per-project requester entries, a capability plan, or step-by-step approval.

Default work includes project reads, search/calculation, analysis scripts, documents, code changes, local branches/worktrees, builds/tests, failure repair, deliverables, read-back, and natural personal-account replies.

Every result must carry workspace, tool, file/test, and delivery evidence.

## Independent high-risk boundary

Ordinary Agent tools cannot push, merge, publish, deploy, write production data, irreversibly delete, control system services, pay, sign contracts, decide HR matters, disclose secrets, or make irreversible commitments.

The boundary is enforced by the pre-tool Hook, per-tool no-network workspace sandbox, direct-file path checks, and a final DWS outbound filter. Configuration errors block the tool.

## Optional Enterprise / Governed Mode

The legacy runtime retains manifests, capabilities, budgets, approvals, recipes, execution leases, side-effect ledgers, and target read-back for regulated and multi-user workflows.

| Legacy level | Example | V3 treatment |
|---|---|---|
| L0 | observe/query/draft | allowed by default |
| L1 | research/analysis/knowledge | allowed inside the project sandbox |
| L2 | documents/code/local work | allowed when reversible and verified |
| L3 | external writes/push/office creation | independent exit or enterprise approval |
| L4 | production/payment/contracts/HR | owner-only high-risk path |

Governed Mode must not make the personal Agent answer “no capability” for an ordinary new project question.

## Memory authority

Personal PRIVATE gbrain Git is the only durable business-knowledge authority; gbrain PostgreSQL is a rebuildable index. Hermes Session DB stores conversation and tool history. Foursday PostgreSQL remains legacy runtime state during migration.

The host bridge requires `default + read-only OAuth`, retrieves exact routed pages, filters sensitive content, and does not expose the credential to Agent tools.

V3.1 queues only low-risk, file-backed `atom`, `prospective`, and pointer `source` candidates. Durable promotion follows requester/session source binding → dedupe → privacy → conflict → an isolated checkout of the owner's PRIVATE gbrain Git → Markdown write-through → default-source projection → exact read-back. Person, project, or time erasure scrubs the encrypted queue and retires promoted pages through the same Git/read-back path. Raw messages, approvals, leases, and temporary execution state never promote.

## Removed from the personal default

- `project_evidence_read` and business-specific totals;
- fixed JSON pointers and deterministic quantity templates;
- per-contact project requesters;
- a new capability or adapter for every question;
- a second Foursday business-memory repository;
- a self-built full Agent Loop.
